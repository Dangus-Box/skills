# Host map: T3 Code

T3's injected "T3 Code orchestration" instructions own the mechanics; where they and this
map differ, they win.

| Need | T3 Code |
|---|---|
| Model ids | Tiers: models.yaml. Check them against `orchestrator_capabilities`, once per thread. |
| Start a helper | Same provider: the native subagent tool with `model`. Another provider, a separate checkout (`isolation:"worktree"`) or background: `delegate_task` with `target.model` and effort in `target.options` (Claude: `effort`; Codex: `reasoningEffort`). With the guard hooks installed (SETUP.md), a delegation whose model is missing or not in models.yaml, or that has no effort, is denied. |
| Role → `role` | Builder → `implementation`; Planner, Strategist, Advisor, Diagnoser → `research`; Designer → `design`; QA → `test`; Reviewer → `review`. |
| List existing | `t3_thread_list`, `t3_worktree_list`. Same task: `t3_thread_send` with only the new instructions. Each review or re-check is a new `delegate_task`. |
| Wake | The delegate's result arrives; follow its `next`. |
| Device loop (QA helper) | `delegate_task` role `test`, passing `hostId` and device `id`; the child calls `device_open` and drives the returned `agent-device` command (`help <command>` lists options). Accessibility snapshot before screenshot; tap and the next snapshot in one shell call. |
| New owner | `t3_thread_launch` when the user's global instructions make rotation a standing request (SETUP.md); otherwise give the user the section 6 pointer to start it. Launch: `message` = the section 6 pointer, `title` = "<topic> (cont.)"; omit `projectId` and model to inherit yours. Work in a worktree: `workspaceStrategy` `{type:"existing_worktree", worktreePath}`; no project: `scratch:true`. Reply with its `link`, then stop. |
| Remove merged worktree | `git worktree remove <path>`; T3 keeps a worktree after its thread is deleted. |
| From a shell | `t3 thread start\|send\|show` take `--provider` and `--model` (`--help`). |
